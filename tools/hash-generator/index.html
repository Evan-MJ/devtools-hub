Understanding Cryptographic Hashes

A cryptographic hash function transforms input data into a fixed-size string of bytes. The same input always produces the same output, but the process is one-way - you cannot reverse a hash to recover the original data. This makes hashes essential for data integrity verification and password storage.

Hash Function Properties

  • Deterministic: Same input always produces same hash
  • One-way: Nearly impossible to reverse the hash
  • Collision-resistant: Two different inputs rarely produce same hash
  • Avalanche effect: Small input change = completely different hash

Hash Algorithms Explained

MD5 (128-bit)

Produces 32-character hex string. Deprecated for security due to collision vulnerabilities. Still used for non-security purposes like checksums and file verification where speed matters more than security.

SHA-1 (160-bit)

Produces 40-character hash. Phase out recommended. Google demonstrated collisions in 2017. Still found in some legacy systems and Git for commit identification.

SHA-256 (256-bit)

Part of SHA-2 family. Currently recommended for most applications. Used in TLS certificates, Bitcoin mining, and general-purpose security.

SHA-512 (512-bit)

Longer variant of SHA-2 with larger block size. Recommended for high-security applications. Used in government standards and enterprise security systems.

Real-World Applications

File Integrity Verification

Download software and compare the published hash with your locally computed hash. A match confirms the file wasn't tampered with during transfer.

Password Storage

Never store passwords in plaintext. Store the hash instead. When users log in, hash their input and compare. Even if the database leaks, attacker only gets hashes, not passwords.

Digital Signatures

Sign documents by hashing the content, then encrypting the hash with a private key. Recipients verify by decrypting and comparing hashes.

Git Commit IDs

Git uses SHA-1 hashes to identify commits uniquely. The commit hash represents the content, author, timestamp, and parent commits - change anything, get a different hash.

Why Hashes Are Not Encryption

Encryption is reversible - you can decrypt with a key. Hashing is not - it's a one-way function. This distinction matters:

  • Use encryption (AES, RSA) when you need to recover the original data
  • Use hashing (SHA-256, bcrypt) when you only need to verify, not recover

Rainbow Tables and Salt

Attackers pre-compute hashes for common passwords (rainbow tables). To defend, add a unique salt to each password before hashing. Even identical passwords produce different hashes when salted. Modern password hashing (bcrypt, Argon2) includes built-in salting.
