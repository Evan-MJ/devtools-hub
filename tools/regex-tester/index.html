What is Regular Expression (Regex)?

A regular expression is a sequence of characters that defines a search pattern. In programming, regex enables sophisticated text matching, extraction, and replacement operations. Whether you're validating user input, parsing log files, or searching through code, regex provides the pattern-matching power you need.

Core Regex Concepts

Literals and Metacharacters

Most characters in regex match themselves literally: abc matches "abc". However, certain characters have special meaning:

  • . - Matches any single character except newline
  • ^ - Matches start of string
  • $ - Matches end of string
  • * - Matches 0 or more of preceding
  • + - Matches 1 or more of preceding
  • ? - Matches 0 or 1 of preceding
  • [] - Character class
  • () - Capture group
  • | - Alternation (OR)

Character Classes

Character classes define sets of characters to match:

  • [abc] - Matches a, b, or c
  • [^abc] - Matches anything except a, b, c
  • [a-z] - Matches any lowercase letter
  • [0-9] - Matches any digit
  • \d - Matches any digit (equivalent to [0-9])
  • \w - Matches word character (a-z, A-Z, 0-9, _)
  • \s - Matches whitespace

Quantifiers

Quantifiers specify how many times to match:

  • * - 0 or more
  • + - 1 or more
  • ? - 0 or 1
  • {n} - Exactly n
  • {n,} - n or more
  • {n,m} - Between n and m

Anchors

Anchors don't match characters but assert position:

  • ^ - Start of string/line
  • $ - End of string/line
  • \b - Word boundary
  • \B - Non-word boundary

JavaScript Regex Flags

In JavaScript, regex flags modify the behavior of the pattern:

FlagNameEffect
gGlobalFind all matches, not just the first
iCase-insensitiveIgnore case when matching
mMultiline^ and $ match line boundaries

Common Regex Patterns

Email: ^[\w.-]+@[\w.-]+\.\w{2,}$
URL: https?:\/\/[\w\-\.]+\.\w{2,}(\/\S*)?
Phone (US): ^\+?1?\s*\(?\d{3}\)?[\s.-]?\d{3}[\s.-]?\d{4}$
Date (YYYY-MM-DD): ^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$
IPv4 Address: ^(?:(?:25[0-5]|2[0-4]\d|[01]?\d\d?)\.){3}(?:25[0-5]|2[0-4]\d|[01]?\d\d?)$
Hex Color: ^#?([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$

JavaScript vs Other Flavors

JavaScript regex differs from PCRE (PHP) and other flavors in several ways:

  • No lookahead/behind variable-length support historically (now supported in modern browsers)
  • No native named groups before ES2018: (?pattern)
  • Unicode property escapes: \p{L} for unicode letters
  • No support for recursive patterns

Practical Use Cases

Form Validation

Validate email addresses, phone numbers, postal codes, and other user inputs before server submission. Catch errors early, improve UX.

Log Parsing

Extract IP addresses, timestamps, error codes, and other structured data from server logs for analysis and monitoring.

Data Extraction

Pull specific information from text: extract prices from reviews, dates from articles, hashtags from social posts.

Search and Replace

Find complex patterns across codebases or documents and replace them with structured transformations.

Debugging Common Regex Errors

Catastrophic Backtracking: (a+)+b can hang on "aaaaaaaaa" without match. Use atomic groups or possessivity where available, or rewrite the pattern.
Forgetting to Escape: cost. matches "cost" + ANY character, not just a period. Use cost\.
Greedy vs Lazy: .* matches as much as possible. .*? matches as little as possible. Choose wisely.
Newline Handling: By default, . doesn't match newlines. Use [\s\S] or the s flag for multiline matching.
