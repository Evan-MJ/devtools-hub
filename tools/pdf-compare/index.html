How Side-by-Side Mode Works

Side-by-side mode renders both PDFs to canvases using pdfjs-dist at your chosen zoom level. Each panel is independently scrollable but the page selector at the top keeps both panels on the same page number, so you never lose alignment while scanning. The renderer uses the PDF's native font and layout so text positioning, image placement, headers, footers, and page numbers appear exactly as in the source. For visual layout comparison - checking if a logo moved, if a table grew, if margins changed - this is the fastest mode. Both panels update together when you click next or previous page.

How Text Diff Mode Works

Text diff mode extracts the text layer from each page using pdfjs-dist's getTextContent API, splits the text into lines, and computes a Myers diff between the two line arrays. The Myers algorithm finds the longest common subsequence and reports insertions, deletions, and equal segments. We render additions with a green left border, deletions with a red left border and strikethrough, and unchanged lines in muted grey. A summary bar at the top shows the count of added and removed lines for the current page. The Jump-to-Next-Diff buttons let you click through every page with differences without manually scanning.

Choosing Between Modes

Use side-by-side when visual layout matters: contracts with redlines visible as crossed-out text, invoices with reordered line items, brochures with image changes, forms with new fields. The eye spots layout shifts, color changes, font swaps, and image swaps much faster than reading text diffs.

Use text diff when only the words matter: code documentation revisions, policy documents, legal text where every word is weighted, articles and manuscripts. Text diff collapses formatting noise so you see only what was added, removed, or kept verbatim. It also handles scanned PDFs poorly (no text layer to extract), so use side-by-side for those.

Common Pitfalls

The most common pitfall is comparing two PDFs that look identical at the byte level but differ visually - this happens when the PDF includes a creation timestamp in the metadata, font subset IDs that change on every export, or image compression that varies slightly between saves. The tool will report zero text diff (correct, because the words are identical) but the page renders will differ. Side-by-side mode catches these cases because it compares pixels, not text.

The second pitfall is scanned PDFs without text layers. Text diff mode returns empty results because pdfjs-dist cannot extract text that does not exist. For those documents, run our PDF OCR tool first to add a searchable text layer, then come back to compare.

The third pitfall is large multi-page documents (over 200 pages). The diff view computes per-page so memory usage stays bounded, but the export report can grow large. For very large comparisons, use the page selector to scope to a specific section rather than building a full report.

How accurate is the text diff?

Text diff is computed per page using the Myers diff algorithm (the same algorithm used by Git for source code diffs). The algorithm finds the longest common subsequence between two strings and reports insertions, deletions, and equal segments. Per-line grouping uses the PDF text Y-coordinate to cluster items into visual lines, so layout-preserving changes (a paragraph moves to the next page but text is unchanged) will still appear as removed + added because the algorithm operates on per-page text blocks.

Technical Details

This tool chains three client-side libraries without any server round trip:

  • pdfjs-dist parses both PDFs, walks each page tree, renders pages to canvases for visual mode, and extracts text content per page for diff mode.
  • pdf-lib builds the optional comparison report PDF, embedding the original PDF pages as visual layers and overlaying diff annotations at correct coordinates.
  • The Myers diff algorithm runs inline in JavaScript to compute line-level differences between page text arrays - the same algorithm used by Git for source code diffs.
