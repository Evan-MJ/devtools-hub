What is Binary Hex Converter?

A binary hex converter is a developer tool that converts between different number systems and text encodings. This tool supports conversions between binary, decimal, hexadecimal, and ASCII text - essential operations for programming and data processing.

How to Use

  • Binary Mode: Enter binary digits (0s and 1s) to convert to other formats
  • Decimal Mode: Enter decimal numbers to convert to binary and hex

How Binary and Hex Conversion Works

This tool converts between three representations of the same underlying bytes: human-readable text (UTF-8), binary (base-2 with digits 0 and 1), and hexadecimal (base-16 with digits 0-9 and a-f). Every character you type is first encoded as a sequence of UTF-8 bytes; each byte is then displayed as either 8 binary digits or 2 hex digits. The letter A (ASCII 65, UTF-8 also 65) becomes 01000001 in binary and 41 in hex. The emoji 😀 (Unicode U+1F600) is encoded in UTF-8 as the four bytes F0 9F 98 80, which becomes 11110000 10011111 10011000 10000000 in binary and F09F9880 in hex.

Decoding works in reverse: the script parses your input by splitting on whitespace, groups digits into 8-bit binary chunks or 2-digit hex chunks, converts each chunk back to a byte value (0-255), and joins the bytes into a Uint8Array that is then decoded as UTF-8 text. Invalid sequences are flagged with an error message rather than silently dropped, so you can spot typos in hex dumps immediately. All conversion happens locally in your browser using standard JavaScript TypedArrays; no data is uploaded.

Frequently Asked Questions

Is this the same as base64?

No. Base-64 uses a 64-character alphabet (A-Z, a-z, 0-9, plus, slash) and encodes every 3 bytes as 4 characters, so it is roughly 33 percent larger than the original. Binary uses only two symbols (0 and 1) and is 8 times larger. Hexadecimal uses 16 symbols and is exactly 2 times larger, which is why hex dumps are the standard format for inspecting raw bytes.

Why does my emoji show as 4 bytes but a regular letter as 1 byte?

UTF-8 is a variable-width encoding. ASCII characters (code points 0-127) fit in one byte. Characters in the Latin Extended range and most common accented letters fit in 2 bytes. CJK characters take 3 bytes. Emoji and other supplementary-plane characters take 4 bytes because their code points exceed the 16-bit Basic Multilingual Plane.

What is little-endian vs big-endian byte order?

When a multi-byte value like the 32-bit integer 0x12345678 is stored in memory, the bytes can be ordered either as 12 34 56 78 (big-endian, most significant byte first, used by network protocols and Java) or as 78 56 34 12 (little-endian, least significant byte first, used by x86 CPUs and most desktop software). This tool displays bytes in the order they appear in your input; if you are debugging a binary file you may need to reverse the byte order manually.

Can I convert a hex color code like #FF8800 to binary?

Yes. Type or paste the hex string (with or without the leading #) into the hex field and the binary field will display the same value as a binary string. FF8800 in hex becomes 11111111 10001000 00000000 in binary. This is useful when learning how RGB color values are stored in image files and CSS.

Are my conversions uploaded to a server?

No. Conversion happens entirely in your browser using JavaScript TypedArrays and the built-in TextEncoder / TextDecoder APIs. You can verify this by opening DevTools Network tab while converting and watching zero requests fire.
